ROS2 Pub GUI 项目结构与运行链路分析
====================================

一、项目定位
------------

本项目是一个运行在服务器/上位机 Linux 环境上的 Qt 图形界面，用于远程控制和监控机器人。

核心能力：

1. 通过 SSH/sshpass 连接机器人侧用户 `rpp@localhost`。
2. 在机器人侧执行 `~/rpp_tools` 目录下的 ROS2 辅助脚本。
3. 提供手动运动控制：前进、后退、左转、右转、停止、升降。
4. 提供自动控制：自动准备、单点导航、抓取任务。
5. 通过 Qt WebEngine 嵌入地图页面和视频页面。
6. 通过本地 SSH 端口转发把机器人侧 8080、8081、9090 暴露给 Qt GUI。
7. 使用日志窗口显示命令输出和状态变化。

五、控制模式状态机
------------------

currentMode 默认值：EmergencyStop

状态图：

             +----------------+
             | EmergencyStop  |
             | 急停/默认状态   |
             +--------+-------+
                      |
          +-----------+-----------+
          |                       |
          v                       v
   +--------------+         +--------------+
   | Manual       |         | Auto         |
   | 手动控制      |         | 自动控制      |
   +------+-------+         +------+-------+
          |                        |
          | 点击急停                | 点击急停
          +-----------+------------+
                      v
             +----------------+
             | EmergencyStop  |
             +----------------+

按钮可用性：

1. EmergencyStop 状态：
   - 手动控制按钮可点。
   - 自动控制按钮可点。
   - 急停按钮始终可点。
   - 当前实现里 manualEnabled/autoEnabled 对 EmergencyStop 也返回 true，因此手动/自动业务按钮本身也会被启用；但多数槽函数内部仍检查 currentMode。

2. Manual 状态：
   - 前、后、左、右、停止、升降可用。
   - 自动准备、单点导航、抓取不可用。
   - 从急停切到手动后，1 秒后远程执行 `start_robot_driver.sh`。

3. Auto 状态：
   - 自动准备、单点导航、抓取可用。
   - 手动方向控制不可用。
   - 单点导航和抓取要求 `isAutoPrepared == true`。

4. EmergencyStop 触发：
   - changeMode(EmergencyStop)
   - 远程执行 `stop_all_terminals.sh`
   - 用于停止相关 ROS2 launch、摄像头 SSH、导航/抓取等进程。

十二、主要数据流
----------------

1. 手动运动控制数据流：

用户按住方向按钮
-> Qt pressed 槽函数
-> runManualCommand()
-> sshpass ssh rpp@localhost -p 2345
-> 机器人侧 ~/rpp_tools/forward.sh 等脚本
-> ros2 topic pub -r 10 /cmd_vel
-> 底盘控制节点接收速度
-> 用户松开按钮
-> stop.sh
-> /cmd_vel 零速度

2. 升降控制数据流：

用户输入高度
-> liftParamEdit
-> Qt 校验 0.0 到 0.3
-> up_down.sh <height>
-> motor_lift_ros.launch.py
-> /motor_lift/set_position Float32
-> 升降电机执行

3. 自动准备数据流：

用户切到自动控制
-> 点击自动准备
-> start_all.sh
-> 启动底盘、机械臂、相机、YOLO、抓取节点、导航节点
-> isAutoPrepared = true

4. 单点导航数据流：

用户输入 X/Y/W
-> Qt 校验
-> navigate_to_pose.sh
-> yaw 转 quaternion
-> ros2 action send_goal /navigate_to_pose
-> Nav2 执行导航

5. 抓取数据流：

用户点击抓取
-> loop_scraping.sh
-> /grasp_node/cmd 发布 "loop"
-> 抓取任务节点执行循环抓取

6. 地图数据流：

ROS2 /map
-> map_bridge.py 可转发到 /web_map
-> rosbridge_server on 9090
-> robot_map_local.html 使用 roslib.js 订阅
-> canvas 绘制地图/路径/机器人/目标点
-> Qt WebEngine 显示

7. 视频数据流：

ROS2 压缩相机图像 /camera/front_camera/color/image_raw/compressed
ROS2 YOLO 调试图 /yolo/dbg_image
-> video_mjpeg_server.py
-> Flask 快照接口 8081
-> video.html 周期刷新 jpg
-> Qt WebEngine 显示

十四、结构性注意点
------------------

1. 当前工作目录不是 Git 仓库，无法通过 git status 跟踪改动。

2. `trajectory.txt` 原来为空，本分析直接写入该文件。

3. 仓库中混有源码、Debug 构建产物、Release 发布产物和 AppImage 依赖库；如果后续整理项目，建议把构建产物和发布包移出源码目录或加入 `.gitignore`。

4. `ros2_pub_gui/` 和 `ros2_pub_gui_github/` 各有一份源码，当前 Qt 工程主要看 `ros2_pub_gui/`；`ros2_pub_gui_github/` 还包含完整 `rpp_tools`，更像发布/同步到 GitHub 的目录。

5. `mainwindow.cpp` 中 SSH 命令有两种写法：
   - 已封装的 `buildRobotSshCommand()` / `buildControlSshCommand()`
   - 多处手写 `sshpass -p 'shihe321' ssh -t -p 2345 ...`
   后续建议统一走封装函数，减少端口、用户名、密码修改时的遗漏。

6. 源码中硬编码了机器人密码 `shihe321`。如果项目要发布或多人协作，建议改为配置文件、环境变量或免密 SSH。

7. `on_singlePointNavButton_clicked()` 中同一个导航命令先 `runManualCommand(cmd)`，后面又 `runAutoCommand(cmd)`，可能导致单点导航被执行两次。结构上更合理的是只走一个执行通道。

8. `navigate_to_pose.sh` 只支持 0/90/180/270 四个角度，但 Qt 侧只检查 W 在 0 到 360，没有限制为这四个值。用户输入例如 45 会通过 Qt 校验，但脚本会报错。

9. `stop_map_runtime.sh` 只停止 rosbridge，不停止 8080 静态 HTTP；`stop_map_service.sh` 才会同时停止 HTTP 和 rosbridge。Qt 的停止地图按钮当前调用的是 `stop_map_runtime.sh`。

10. `updateSplitterGeometry()` 仍引用 `mainSplitter`，但当前布局实际使用 `outerSplitter/contentSplitter/leftSplitter`。因为 `mainSplitter` 默认是 nullptr，该函数多数情况下直接返回，实际尺寸主要由 QSplitter 和 layout 管理。

11. 手动控制的 pressed 脚本使用 `ros2 topic pub -r 10` 持续发布，released 时通过 `runManualCommand(stop.sh)` 会先 kill 上一个进程，再发布停止命令，这个设计符合按住运动、松开停止的控制模型。

12. 地图和视频页面依赖 SSH 隧道已建立，否则 Qt WebEngine 加载的是服务器本地地址，会访问不到机器人侧服务。
